# medit — портфолио с админкой (Full-Stack CMS)

Полноценное портфолио разработчика с защищённой админ-панелью. Весь контент хранится на сервере (SQLite через `better-sqlite3`, файл `data/portfolio.db`), редактируется через `/admin` без правок кода. Никаких демо-данных в localStorage и неработающих кнопок — каждая функция реально работает.

## Стек

- **Next.js 14 (App Router) + TypeScript + Tailwind CSS**
- **SQLite (better-sqlite3)** — реальная серверная БД, WAL-режим
- **bcryptjs** — хэширование паролей, **HMAC-SHA256** подписанные сессии (httpOnly cookie, 7 дней)
- **Firebase Authentication** — регистрация по email/паролю, Google/Gmail и анонимный вход
- **lucide-react** — иконки, **RU/EN i18n**, тёмная/светлая тема

## Быстрый старт

```bash
cd portfolio
cp .env.example .env.local   # отредактируйте секреты!
npm install
npm run build
npm start                    # http://localhost:3000
```

Для разработки: `npm run dev`

| Переменная | Назначение |
|---|---|
| `SESSION_SECRET` | Секрет подписи сессий. Сгенерировать: `openssl rand -hex 32` |

| `NEXT_PUBLIC_SITE_URL` | Базовый URL для sitemap/robots (например `https://example.com`) |
| `NEXT_PUBLIC_FIREBASE_*` | Конфигурация Firebase Web App для входа посетителей |
| `PORT` | Порт сервера (по умолчанию 3000) |

**Данные администратора:** почта `medit451@gmail.com`, пароль `03887388` — заданы в `.env.local` и в БД. Смените пароль через раздел «Безопасность» в админке (или `.env` + удаление `data/portfolio.db`) перед публикацией.

## Что внутри

### Регистрация и экран приветствия (при входе на сайт)
При первом заходе на любую публичную страницу открывается обязательное окно **«Добро пожаловать на medit»**. Пока посетитель не выберет способ входа, контент не считается открытым:
- **Войти через Google** — Firebase Google/Gmail OAuth;
- **Зарегистрироваться по email** — Firebase Email/Password;
- **Зайти как наблюдатель** — Firebase Anonymous Auth (это реальная анонимная учётная запись, а не флаг в `localStorage`);
- **Зайти как админ** — серверный вход в CMS: `medit451@gmail.com` + `03887388`, после успеха открывается `/admin`.

Firebase сохраняет сессию пользователя в браузере, поэтому после перезагрузки повторная регистрация не требуется. Любой пользователь с зарегистрированным email или Google/Gmail автоматически получает роль `admin`: его Firebase ID token проверяется сервером, после чего создаётся защищённая серверная сессия и в шапке появляется кнопка «Админ». Анонимный вход остаётся режимом наблюдателя без доступа к CMS. После регистрации пользователь остаётся на публичной странице. На страницах `/admin` окно не показывается и публичная шапка/подвал скрыты.

#### Что включить в Firebase Console
В проекте `portfolio-23104` откройте **Authentication → Sign-in method** и включите провайдеры **Anonymous**, **Email/Password** и **Google**. В **Authentication → Settings → Authorized domains** добавьте домен локального сайта и настоящий production/preview-домен. Без этого Google или регистрация будут возвращать понятную ошибку от Firebase.

### Публичная часть
- `/` — Hero, About, Skills (группировка по категориям, анимированные бары), Projects, Experience (таймлайн с фильтрами по типам), Contact
- `/projects` — все проекты с поиском и фильтром по категориям
- `/projects/[slug]` — страница проекта: описание, технологии, галерея, ссылки на GitHub/Live Demo, похожие проекты
- `/about`, `/contact` — отдельные страницы
- Тёмная тема по умолчанию + светлая (переключатель в шапке, сохраняется в localStorage)
- RU/EN переключатель языка (сохраняется в localStorage)
- Форма контактов → сообщения сохраняются в БД и видны в админке
- SEO: динамические мета-теги из настроек, Open Graph, `sitemap.xml`, `robots.txt`, кастомная 404
- Скачивание резюме (PDF) — ссылка настраивается в профиле

### Админ-панель (`/admin`, серверная защита)
- **Панель управления** — статистика, последние проекты/сообщения, быстрые действия, размер БД
- **Проекты** — полный CRUD: slug (автогенерация), категории, статусы, обложка, галерея, технологии, GitHub/Live Demo, публикация
- **Навыки** — CRUD, уровни 0–100, категории, иконки Lucide, сортировка ↑↓
- **Опыт** — CRUD по типам (работа/стажировка/образование/сертификаты/достижения), сортировка
- **Сообщения** — входящие с формы, фильтры все/прочитанные/непрочитанные, просмотр, «отметить прочитанным», ответ по email, удаление
- **Медиатека** — загрузка изображений/PDF до 5 МБ (drag & drop), копирование ссылки, удаление файла с диска
- **Профиль** — имя, должность, bio, about, специализация, интересы, статистика, контакты, соцсети, аватар, резюме
- **Настройки** — название сайта, логотип, favicon, тексты Hero-кнопок, видимость секций, SEO/OG
- **Безопасность** — смена пароля (проверка текущего, минимум 8 символов)
- **Резервные копии** — скачивание БД (`.db`) и экспорта всего контента (JSON)

### Безопасность
- Все `/admin/*` страницы и все мутирующие API защищены серверной проверкой подписанной сессии (middleware + проверка в каждом API-роуте + layout)
- Пароли — только bcrypt-хэши в БД; секреты — только в `.env`
- Валидация email, размеров и типов файлов на сервере; экранирование при выводе

## Структура

```
app/
  page.tsx, about/, contact/, projects/, projects/[slug]/   — публичные страницы
  admin/(protected)/{page,projects,skills,experience,messages,media,profile,settings,security}
  admin/login/                                               — вход
  api/auth|profile|settings|skills|projects|experience|messages|media|admin/*
components/   Navbar, Hero, About, Skills, Projects, Experience, Contact, Footer, Toast, Modal, Reveal, AdminShell
lib/          db.ts (схема + seed), auth.ts (сессии), i18n.tsx (RU/EN), utils.ts
data/portfolio.db                                            — SQLite (создаётся автоматически)
public/uploads/                                              — загруженные файлы
```

## Production notes

- Перед деплоем задайте сильные `SESSION_SECRET`, `ADMIN_EMAIL`, `ADMIN_PASSWORD` и `NEXT_PUBLIC_SITE_URL`.
- БД — один файл SQLite: делайте резервные копии через админку (Настройки → Скачать БД) или копированием `data/portfolio.db`.
- Для PostgreSQL/Supabase в будущем слой `lib/db.ts` — единственное место, которое нужно заменить на клиент Postgres; API-роуты и UI не изменятся.
